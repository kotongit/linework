# Linework for Windows: Design

Date: 2026-11-01
Repo: https://github.com/kotongit/linework, in `windows/`
Behaviour authority: the Mac app in `Sources/`, as of commit 542dbdc and later. Where this spec is silent, Windows does what the Mac app does.

## Purpose

The same app for Windows 10 and 11, with the same features and look, reading the same library folder. A library made on one system opens on the other.

## Success criteria

- All features of Linework 2.0 work, except as §5 lists.
- A library made by the Mac app opens with the same photos, ticks, sessions, benchmarks and canvases, and the Mac app can open it again afterwards.
- `Linework-Setup.exe` installs on a Windows PC with nothing else installed.
- Each stage in §8 ends with a working installer.

## Out of scope

- Code signing, Microsoft Store, ARM64 builds (x64 runs under emulation on Windows 11 ARM), macOS changes, new features.
- Merging or live sync between two computers. The Mac spec's "not on two computers at once" advice applies.

## 1. Technology

| Item | Choice |
|---|---|
| Runtime | .NET 10 (long-term support to 2028), bundled by the installer |
| Screens | WPF |
| Minimum system | Windows 10 version 1809, 64-bit |
| Third-party code | ONNX Runtime and one person-detection model only. Tests may use xUnit. |
| App identity | "Linework", publisher hyprsea solutions, version from one place |

## 2. Structure

```
windows/
  Linework.sln
  Linework.Core/        net10.0, no Windows APIs: logic and file formats
  Linework.Core.Tests/  xUnit; runs on Mac and Windows
  Linework.App/         net10.0-windows, WPF: screens, stores, platform services
  installer/            Inno Setup script
.github/workflows/windows.yml
shared/fixtures/        Sample library and expected values used by both apps' tests
```

`Linework.Core` follows the Swift `LineworkCore` type by type, keeping names unless C# convention requires otherwise: pure decisions in Core, and stores only read, write and publish.

## 3. Compatibility with the Mac app

- **Library format:** identical to the Mac spec §3: layout, `library.json`, `version` and `items` envelopes, JSON keys, ISO 8601 dates, uppercase UUIDs, lowercase SHA-256, tick keys including `-rN` and `cN`, and `canvas.json`.
- **Unknown JSON fields are preserved or ignored without failure, and newer versions stop the library from opening,** as on Mac.
- **File rules stay:** atomic writes, damaged files set aside and never overwritten, unreadable files stop the library from opening, the library is never recreated at a missing path, missing photos keep their records, lost photo records pause the Finder check.
- **Plan data:** one script extracts the JSON from `PracticePlanData.swift` into an embedded resource in `Linework.Core`. A test fails if the two differ.
- **Copy:** every line of text matches the Mac app, including s.e.a.'s notes.
- **Shared fixtures:** a sample library, tick keys, schedule mappings, and streak and heatmap values are generated by the Mac code. Both test suites check against them.

## 4. Windows platform services

| Need | Windows approach |
|---|---|
| Keep screen awake in a session | `SetThreadExecutionState` |
| Delete | Recycle Bin; if unavailable, ask before erasing |
| Library location memory | Path in settings. If moved, the chooser says so and asks, because Windows has no bookmark equivalent. |
| Preferences | `%APPDATA%\Linework\settings.json` |
| Thumbnails | `%LOCALAPPDATA%\Linework\Thumbnails`, by hash |
| Default library | `Documents\Linework Library` |
| Finder changes (now File Explorer) | Same checks when the app comes to the front |
| Fullscreen session | Borderless window covering the current monitor |
| Glass | Mica on Windows 11 22H2 and later, through `DwmSetWindowAttribute`; solid ground colour otherwise. The Transparency setting applies only where Mica is available. |
| Image reading | Windows Imaging Component |
| Auto-crop | Person detection with a small permissively licensed ONNX model on CPU, falling back to the full frame with the "no figure found" flag |
| Sounds | Short original WAV files bundled with the app: tick, pose chime, note chime, celebration. Apple's sounds can't be redistributed. |
| Font | Inter Tight static instances at the weights used, bundled, with its license |

## 5. Differences from the Mac app

- Ctrl replaces ⌘, and menus sit inside the window. WPF shows a slim File and Go menu above the top bar.
- A photo format Windows can't read, such as HEIC without Microsoft's extension, keeps its record and shows a placeholder and a notice, and sessions skip it.
- Canvas names follow the stricter of the two systems' rules: no `< > : " / \ | ? *`, no trailing dot or space, and no reserved names like `CON`. A folder arriving from a Mac with an unusable name is left alone and reported.
- Auto-crop results may differ slightly from the Mac's. Existing crops are never recalculated.

## 6. Installer

Inno Setup builds `Linework-Setup.exe` in GitHub Actions from a self-contained .NET publish. It installs per user, so no administrator rights are needed, adds a Start menu entry and uninstaller, and leaves the library alone on uninstall. Without a signing certificate, SmartScreen warns on first run, and the README shows **More info**, then **Run anyway**.

## 7. Testing

- **On this Mac:** `dotnet test` for all of Core, including file behaviour and fixtures. `Linework.App` compile-checks with `EnableWindowsTargeting`.
- **On GitHub's Windows machines, at stage ends:** build, Core tests, a debug harness that drives real views and stores against a scratch library, screenshots of each screen in light and dark, and the installer. Screenshots and the installer are saved as artifacts for review.
- **Offscreen renders aren't proof of** Mica, sound, fullscreen, drag and drop or high-DPI behaviour.
- **On the user's Windows PC, if available, at stage ends:** install, SmartScreen steps, live session, sounds, glass, high-DPI scaling, opening a real library copied from the Mac.

## 8. Stages

1. **Library and sessions:** chooser, welcome, settings, library, import, Finder check, crop editor, auto-crop, session setup, player, main menu.
2. **Plan and s.e.a.:** Today, Path, Calendar, ticking, repeats, celebrations, notes, plan guide.
3. **Benchmarks and Freehand:** Progress, attempts, comparison, canvases and all canvas tools.

The user can stop after any stage. Features not yet built are hidden, not shown disabled.

## 9. Risks

| Risk | Handling |
|---|---|
| Visual details differ from SwiftUI's | Rendered screens compared against the Mac's; live checks on the PC |
| WPF behaviour can't be seen from the Mac | Debug harness on GitHub's Windows machines; anything unverified is listed for the user |
| The two apps' formats drift | Shared fixtures in both test suites |
| Limited Actions minutes on a private repo | Windows runs only at stage ends or by hand; the Mac runs Core tests locally |
| Model license or size | Checked before bundling and recorded in `LICENSES/` |
